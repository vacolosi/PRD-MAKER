What the app calculates

It calculates closed-loop liquid friction loss: actual-fluid head and loss-equivalent psi. It does not calculate static lift, pump selection, pump certification, NPSH, balancing, or automatic pipe sizing.

Normal calculation workflow

1

Define the system

Set fluid, temperature, pump connection, nodes, and the safety factor in System.

2

Add physical sections

Describe each real pipe/equipment segment once in Sections.

3

Build complete routes

Use Circuits to put the physical sections in pump-discharge-to-pump-suction order.

4

Review and confirm

Resolve diagnostics, confirm applicability for each loss, acknowledge the safety factor, and inspect Results.

5

Accept or export

Only a calculation-ready result can be accepted locally. Use Files & report for JSON, CSV, and print.

System

System

Fluid and temperature

Choose the named water/glycol reference and the mean operating temperature. These determine the fluid density and viscosity used by the engine.

Pump connection

Where the loop starts and ends

Select the pump discharge node and pump suction node. A valid circuit must form a continuous route between them.

Nodes

Connection points

Nodes are named connection points such as a supply split, terminal, or return merge. Sections connect one node to another.

Safety factor

Explicit review gate

Choose the loss categories that receive the safety factor, enter a percent, and explicitly acknowledge it—even when it is zero.

Sections

A section is one physical piece of the system: a pipe run plus any fittings, valves, or equipment losses located in that piece. Create it once, even when several circuits use it.

Pipe data

Set the from/to nodes, actual length, and catalog or custom pipe geometry. The engine calculates the straight-pipe loss from these inputs.

Non-pipe losses

Add manual K, equivalent length, preset elbow, Cv, direct psi, or direct head. These are separate from pipe friction.

Section PD

The card header shows the evaluated total for that physical section when its route and applicability gates are complete. Unavailable is deliberate: it never means zero.

Confirm current basis

This records that a loss applies at the current flow, fluid, temperature, and geometry. Relevant edits make that confirmation stale.

Circuits

A circuit is a complete water route through the model. It tells the engine which physical sections are in series for a terminal and which ones are shared with other terminal routes.

pump discharge → supply sections → terminal section → return sections → pump suction
  • Supply path: ordered supply sections from pump discharge toward the load.
  • Terminal section: the load or terminal equipment for that route.
  • Return path: ordered return sections back toward pump suction.
  • Terminal design GPM: the design flow for that complete route. The engine derives shared-section flow by adding terminal flows; section GPM is never typed directly.
Why a circuit matters: Without a complete route, the app cannot safely know the flow through each section, so it cannot make a governing-head claim.

Results / Show the math

System headline

The governing path is the highest complete circuit path after the configured safety factor. It is not the sum of every section in the system.

Section totals

One row per physical section, including its derived flow, total head, psi, and availability. Parallel branches are alternatives, so there is no fake grand-total row.

Blocking diagnostics

Lists every unresolved engine, topology, applicability, or safety-factor issue. Use it as the checklist for making a result calculation-ready.

Show the math

Select a circuit to inspect velocity, Reynolds number, friction factor, individual losses, cumulative detail, and the engine’s public outputs.

Files & report

  • Save JSON / Open JSON: save or load portable project inputs locally. Imported acceptance is historical only; it is never automatically trusted as local acceptance.
  • Accept reviewed result: records a locally reviewed snapshot only after all calculation gates are satisfied.
  • Print report / Download itemized CSV: create local outputs from the current app state.
  • Reset to synthetic example: discard the local draft and restore the built-in starter sample.

Loads the one diagram-supported selected path: Sections 07–16, terminal 17, and Sections 18–31. It is intentionally partial, inferred, unaccepted, and not legacy-equivalent.

Why only one provisional path? The workbook shows additional branches and coils, but it does not provide enough identified pipe/terminal records to construct every branch without inventing data. A full calculation-ready network needs an engineer to define and review those missing routes.
